# ORC-24 native/domain authority proposal — pending root assessment

This is a narrow proposal, not a new consent rule or approval to retry a refused tool. It compares candidate 0d39dc1e with accepted 934b85b9. The saved native design requires explicit decisions; it does not establish a permanent automation ban. Settings opt-ins, Secrets and stale Agents protection, execution-time revocation, authenticated call origin and every actual person_only/classifier/tool refusal remain binding.

New candidate restrictions requiring assessment:

- Guarded::LocalIntegrationQuestion currently always refuses under both Settings grants. It was added by ORC-24, not present in 934b. Mounting it for the entire resolver/preparation phase also blocks ordinary edits. Proposal: classify actual authority decisions, not every field or phase. Preserve the existing global refusal while any real protected question is mounted; no endpoint/input retry of an actual refusal.
- Ordinary Inspect/Refresh now perform real work. Mutating Synthetic callbacks return a visible refusal without changing classification. Raw editor discard still retains the candidate when that input origin is refused. Proposal: assess ordinary candidate edit/save/discard separately from protected decisions under accepted scope.
- merge_run currently returns person_required for every ready run. Proposal: restore the accepted authenticated legacy path when no managed decision exists; route managed operations through the same typed fresh-state authority boundary as the native page.
- A new test asserting these broader bans is not acceptance evidence. Final tests must demonstrate accepted ordinary work, execution-time revocation and genuine protected refusals, without answering a live protected question.

No protected classification change is authorized by this proposal. Root and the independent reviewer must settle the mapping before those changes. No QA slot is requested or used here.
