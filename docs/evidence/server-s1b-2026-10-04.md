## Changes

- Core adds `ClaimId`, validated `TaskRevision`, pure claim transitions over explicit timestamps and
  `RepositoryIdentity`. HTTPS, SSH and scp-like identities match; local or absent origins are refused, and
  credential-bearing URLs are normalized without retaining their credentials.
- The server calls core's existing task completeness, queue/edit and ORC-39 organization rules. Small pure checks
  were factored out for shared pipeline slugs and reported run phases. Blocking links now normalize in core to one
  gate per task, keeping task snapshots and history consistent for both local and shared tasks.
  Organization, dependency gates, tag validation and history use core types. No HTTP or database code enters core.
- `orchester-api` remains types only. Its wire adapters expose the specification's snake-case enums while keeping
  existing core serialization intact. Request shapes reject unknown fields; nullable PATCH fields distinguish
  absent values from explicit nulls. Structured errors carry current tasks, claims, owners or validation details.
- Schema 2 migrates schema 1 forward in an immediate transaction, preserving accounts and audit history. Projects,
  membership roles, tasks, tags, links, organization history, claims, claim history and persisted events live in
  the server database. History tables reject updates and deletes. No local run contents or secrets are uploaded.
- Task numbering, unique repository creation, idempotency, revision checks, claims, tag rewrites and last-owner
  checks commit atomically. Idempotency stores the first response snapshot, so retries after later edits still
  return that first result. Failed batches roll back counters, tags and history as well as tasks.
- Claim freshness and session expiry use the clock after the database transaction begins. Tests hold another
  SQLite writer while advancing the clock to cover requests that wait for a transaction.
- Removing a member or disabling a user releases claims in the same transaction. A membership lifetime id
  invalidates existing streams even when a user is removed and re-added at the same test time.
- SSE replays persisted snapshots from `Last-Event-ID`, checks session and membership validity during replay and
  backpressure, emits 20-second keep-alives, resets expired cursors and closes on revocation or server shutdown.
  Replay batches at most 64 events and 1 MiB of payload, with a single larger snapshot sent alone, and uses a bounded
  output channel. Retention pruning runs on successful sharing writes at most once per minute, using `(project, at)`.
  The retention floor survives pruning;
  expired events are excluded even before a subsequent write prunes their rows.
- Task numbers preserve core's `u32` range, with an exhausted counter at `u32::MAX + 1`. Budget and duration limits
  preserve the full `u64` range as decimal SQLite text rather than lossy REAL values.
- No desktop, UI, runner, local store or hosting configuration changes. No new runtime dependencies: the existing
  workspace axum dependency enables its `query` feature for repository lookup. Its transitive URL decoder appears
  in `Cargo.lock`; all server dependencies remain from the specification's table. API round-trip tests reuse the
  existing workspace `serde_json` as a dev-dependency.

## Independent review findings fixed (2026-10-04)

Review request: `.tmp/review-server-s1b/FIXES-FOR-CODEX.md`, covering the security/concurrency and spec/domain reviews.
The previous 28 passing functional tests did not establish that these resource and contract cases were sound.

| Finding | Change and regression evidence |
| --- | --- |
| R1 heartbeat amplification | Freshness updates write no events or full task snapshots. Requests accept at most 256 ids and 12 calls per 60-second window per session, atomically checked before the heartbeat writer. Tests use a 900 KB brief and compare event count and stored payload bytes before/after; test the list cap, concurrent allowance, independent session and exact window reset. |
| R2 pruning on every append | Prune at most once per minute on successful sharing writes. Install `(project, at)` on new and pre-review schema-2 databases; expired-row queries explicitly use it. A 300,000-recent-event fixture and prune-observation trigger prove two 50-task batches prune once, then prune again at the next minute; the query plan uses the retention index. |
| R3 stream exhaustion | RAII permits limit SSE to 8 connections per session and 16 per user, including trusted proxies. Full capacity returns `429` with `Retry-After: 1`; disconnects and session revocation return permits. A loopback proxy-trust test fills both limits, admits another user and an ordinary request, and checks capacity reuse. |
| C1 client error details | Detail variants reject unrelated fields; `Claim` requires an explicit `claim` field, including null. API round trips cover remote, owners, current task, every claim error code, queue reasons/missing details, edit and organization errors. `Missing` remains a required, exercised queue-error shape rather than dead code. |
| C2 batch foreign keys | Build the planned organization graph and validate all references/cycles before saving links or tags. Unknown tag ids return `422 organization` / `tag_not_found`; unknown task links return `422 invalid`. Both tests include an earlier valid task and verify full rollback and no number gap. |
| C3 uploaded finished runs | Coordinator's specification change recorded in Shapes and UploadTask text: required `has_run: bool` retains any local run, including ended runs; `claim: true` implies it. Share and Import of queued, unclaimed tasks with finished runs permit subsequent content edits. |
| m1 duplicate links | Core normalizes to one link per task, with the last supplied gate winning. Core round trip and server task/history comparison tests assert identical links. |
| m2 holder take freshness | Taking one's current claim refreshes its heartbeat without changing its id, kind (except manual-to-run upgrade), or start time. Tests cover explicit core times and a run take after 16 minutes, followed by a refused fresh takeover. |
| m3 release error | The endpoint table now records `422 not_editable { reason: "stop_run_first" }`; the existing active-agent release regression passes. |
| m4 admin relationship | Project role is optional; non-member admin PATCH returns null while ordinary project/task reads remain member-only. Covered alongside the project event test. |
| m5 unused paths | Remove unused optional gate/phase wire adapters and the server's unreachable `organization / blocked` response path. Core's runner preflight `Blocked` error remains in use outside S1b. Queue `Missing` details are exercised by the repaired client contract tests. |
| m6 claim revisions | Take, release, takeover and forced release preserve the content revision. A claim/revision regression verifies an editor's pre-claim revision still succeeds; actual content/organization/tag changes continue to advance it. |
| m7 missing event/identity tests | Assert members events on add and role change, complete project event metadata, exact not-member owners, and exact `LocalOrigin` errors for local paths. |
| m8 replay round trips | Read and deliver bounded event batches rather than authenticate/read each individual event. Loopback tests replay 3,000 exact ordered events and large 900 KB snapshots across byte-limited batches without loss. |
| m9 collision/activity metadata | Foreign-project task-id collisions return a generic `409 conflict` without task/project details; same-project or repeated batch ids retain `id_taken`. A test uses a non-member's foreign id and verifies unchanged numbering. Global event-sequence gaps remain an explicitly documented S1b metadata tradeoff; generic collision status can still imply a collision. |
| m10 phase status | Move S1b out of Done and back under S until merge; Phasing boxes remain unticked pending review/merge. |
