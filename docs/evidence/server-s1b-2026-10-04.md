## Changes

- Core adds `ClaimId`, validated `TaskRevision`, pure claim transitions over explicit timestamps and
  `RepositoryIdentity`. HTTPS, SSH and scp-like identities match; local or absent origins are refused, and
  credential-bearing URLs are normalized without retaining their credentials.
- The server calls core's existing task completeness, queue/edit and ORC-39 organization rules. Small pure checks
  were factored out for shared pipeline slugs and reported run phases; local behavior and storage remain unchanged.
  Organization, dependency gates, tag validation and history use core types. No HTTP or database code enters core.
- `orchester-api` remains types only. Its wire adapters expose the specification's snake-case enums while keeping
  existing core serialization intact. Request shapes reject unknown fields; nullable PATCH fields distinguish
  absent values from explicit nulls. Structured errors carry current tasks, claims, owners or validation details.
- Schema 2 migrates schema 1 forward in an immediate transaction, preserving accounts and audit history. Projects,
  membership roles, tasks, tags, links, organization history, claims, claim history and persisted events live in
  the server database. History tables reject updates and deletes. No local run contents or secrets are uploaded.
- Task numbering, unique repository creation, idempotency, revision checks, claims, tag rewrites and last-owner
  checks commit atomically. Idempotency stores the first response snapshot, so retries after later edits still
  return that first result. Failed batches roll back counters, tags and history as well as tasks.
- Claim freshness and session expiry use the clock after the database transaction begins. Tests hold another
  SQLite writer while advancing the clock to cover requests that wait for a transaction.
- Removing a member or disabling a user releases claims in the same transaction. A membership lifetime id
  invalidates existing streams even when a user is removed and re-added at the same test time.
- SSE replays persisted snapshots from `Last-Event-ID`, checks session and membership validity during replay and
  backpressure, emits 20-second keep-alives, resets expired cursors and closes on revocation or server shutdown.
  Replay fetches one snapshot at a time and uses a bounded output channel. The retention floor survives pruning;
  expired events are excluded even before a subsequent write prunes their rows.
- Task numbers preserve core's `u32` range, with an exhausted counter at `u32::MAX + 1`. Budget and duration limits
  preserve the full `u64` range as decimal SQLite text rather than lossy REAL values.
- No desktop, UI, runner, local store or hosting configuration changes. No new direct dependencies: the existing
  workspace axum dependency enables its `query` feature for repository lookup. Its transitive URL decoder appears
  in `Cargo.lock`; all server dependencies remain from the specification's table.
