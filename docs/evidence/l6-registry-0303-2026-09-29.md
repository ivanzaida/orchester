The approved lurq 0.30.3 release was published by the [Publish crates workflow](https://github.com/ivanzaida/lurq/actions/runs/36536902605), and crates.io reported version 0.30.3. Orchester now uses that registry crate, with checksum `d7d84e001c71119ca1c8f088e408b749823f2a7ba63a9df2a1d2e940561a80a9` in `Cargo.lock`. There is no local lurq path patch. The independently reviewed source candidate was worktree `codex/l6-registry-0303` at base `fc3914647240d920f644ab2c9128ea2f96dc11ba`. - `cargo test -p orchester-desktop --test form_keyboard window:: --locked` passed 11/11. An earlier attempt was interrupted when free disk space fell below the 1 GiB gate; the complete rerun passed after separate, rebuildable target data was cleared.

- The independent verifier built the runner and MCP desktop with `--locked` from the registry dependency and used its own copied binaries, database, and MCP discovery directory.

## Independent live verification

The verifier launched only its own desktop PID 52268 with the no-focus environment flag. Exact-PID MCP reported `main.focused: false` at launch, after two resizes, and after two navigation clicks. The host foreground watcher started before the app and recorded 951 post-marker samples, 187–204 ms apart: foreground PID 10132 throughout, never the verifier PID. The app closed through its own MCP endpoint, and the watcher returned `pass`. The observation proves no focus at sampled instants; a shorter activation between samples cannot be excluded.

The verifier exported live Pencil nodes `ZBoBm` (Welcome), `QQmsI` (Windows chrome), and `pmOpt` (status bar) through Pencil MCP. It compared the 2160×1440 Welcome design with the exact-PID app capture cropped to the same size, region by region. Result: **0 blocking, 0 major, 1 pre-existing minor** copy difference (`Choose the project folder` in Pencil versus `Connect a repository` in the app). Unimplemented setup steps remained visibly unavailable. The unfocused state has no Pencil specimen; the exact-PID MCP and foreground watcher verify it. Full screenshots, timeline, source hash, and verdict are in `.tmp/verify/l6-registry-0303/report.md`.

The stable Orchester installation, its database, and `data/orchester.pen` were not changed. Live macOS focus behavior was not run in this Windows integration.
