# ORC-61: Send now reaches an agent after its running tool call (2026-10-02)

Live checks of how each agent CLI takes a person's message while its turn runs, made before the runner
was built on them (`docs/design/orchester-workspace.md`, "Conversation (merged with Activity)",
Decisions: *Send now lands after the running tool call*). Scripts: `.tmp/orc-61-steer/` (not tracked).
Both on Windows 11; macOS is not checked yet.

## Codex 0.159.2 — App Server `turn/steer`

A thread in a scratch folder (`approvalPolicy: never`, `sandbox: read-only`, the account's default
model), and a turn asked to run `python -c "import time; time.sleep(10); print('slept')"`, then reply.

1. `item/started` `commandExecution` (Codex wraps it in `pwsh.exe -Command "…"`).
2. One second later the probe sent `turn/steer` with `expectedTurnId` the running turn and the text
   *While you work: when you reply, include the word BANANA.* Codex answered at once:
   `{"turnId": "<the running turn>"}`.
3. `item/completed` `commandExecution` (`completed`) nine seconds later, **then** `item/started` and
   `item/completed` `userMessage` with the steered text.
4. The final `agentMessage`: *The command completed and printed “slept”; BANANA.*, then `turn/completed`.

The steered message reached the model after the running command, in the same turn. `turn/steer` while no
turn runs answers `{"error": {"code": -32600, "message": "no active turn to steer"}}`.

## Claude Code 2.1.286 — stream-json input

`claude -p --input-format stream-json --output-format stream-json --verbose --replay-user-messages --model
haiku --setting-sources "" --strict-mcp-config --disable-slash-commands --allowedTools Bash`, the prompt as
the first stream-json user message.

- **During a tool call.** The prompt asked for the same 8-second Python sleep through Bash. One second
  after the `tool_use`, the probe wrote another user message (*…include the word BANANA.*). Output: the
  `tool_result` (*slept*), **then** the message printed back (`type: user`, `isReplay: true`), then the
  reply *The command slept for 8 seconds and printed the output — BANANA.* and one `result`
  (`num_turns` 1).
- **After the last tool call.** A prompt with no tool use (*Write a 150-word paragraph…*) and a second
  message written right after `system/init`: the first `result` came without it; the CLI then printed
  `system/init` again, the second message back (`isReplay`), a new reply and a second `result`, even
  though the probe closed standard input after the first result.

The message reaches Claude Code after the running tool call, or, when its turn has no tool call left,
as its next turn after the result.

## What the runner does with it

See `docs/architecture/storage.md`, "Send now (ORC-61)". The fake CLIs of the runner's tests
(`orchester-fake-codex`, `orchester-fake-claude`) take a message the same way; `cargo test -p
orchester-runner --features test-agent --test send_now send_` covers both CLIs.

## Live, through the runner

After the runner was built, the ignored tests `send_now_live_codex_takes_a_message_mid_turn` and
`send_now_live_claude_takes_a_message_mid_turn` ran a real step on each CLI (npm's `codex.cmd` 0.159.2 on
the account's `gpt-6.1-sol`, `claude.cmd` 2.1.286 on `haiku`): the agent ran the 20-second command, the
test stored a message sent now (*include the word BANANA in your step result's summary*) and woke the
run. Both passed (44 s and 48 s): the message was delivered mid-turn and acknowledged, the run succeeded
in one invocation, and the agent's text named BANANA. Repeat with

```
ORCHESTER_LIVE_CODEX=<codex program> cargo test -p orchester-runner --features test-agent --test send_now send_now_live_codex -- --ignored
ORCHESTER_LIVE_CLAUDE=<claude program> cargo test -p orchester-runner --features test-agent --test send_now send_now_live_claude -- --ignored
```

on the CLI's own sign-in. Not run on macOS yet.
